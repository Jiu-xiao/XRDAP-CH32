# Boards

[中文](boards.md)

This document lists the pins, keys, lights, core clock and radio of each board XRDAP-CH32 supports. On every board the probe is the USB device `1D50:6199` with 1024-byte DAP packets; each board has its own bcdDevice (`xrdap/probe/family.hpp` in XRDAP-Core).

## wdap

The high-speed wireless DAP board: CH32V307RCT6, 12 MHz crystal, high-speed USB, an SX1281 radio module, product name `XR-DAP-V307`. The `wdap` firmware runs at 216 MHz, `wdap-144` at 144 MHz.

| Use | Location |
|---|---|
| SWCLK | 2×6 header pin 3 (TCK_O, PB3) |
| SWDIO | 2×6 header pin 4 (TMS_O, PB5) |
| Target reset | 2×6 header pin 5 (RST_O, PC1) |
| Power output | 2×6 header pin 1 3V3, pin 7 5V; left open when the target has its own supply |
| Bootloader key, pairing key | KEY2 |
| Status lights | 8 WS2812B, data line PB15 |

The status lights show the connection, the radio, pairing and DAP activity by the rule shared by the XR-DAP family, described in the "Status lights" section of the XRDAP-Core README; a rainbow runs once at power-up.

The radio has two rates: high (default), GFSK at 2 Mb/s, up to 255 bytes per packet, a 1024-byte message in at most 5 packets; low, FLRC at 1.3 Mb/s, up to 127 bytes per packet, a message in 9 packets. Pairing and the start of a session use the control channel F (2448.5 MHz); the data channel is chosen in 2402–2481 MHz.

The chip has 64 KB of RAM: 4 DAP packets (reported by DAP_Info) and a 4096-byte sampling buffer (reported by the vendor extension's INFO).

## v305

A CH32V305 board with the WCH-LinkE circuit: CH32V305FBP6, 12 MHz crystal, high-speed USB, no radio, product name `XR-DAP-V305`. The `v305` firmware runs at 216 MHz, `v305-144` at 144 MHz.

| Use | Pin |
|---|---|
| SWCLK | PB13 (wired to PA14 on the board) |
| SWDIO | PA9 (bonded to PA13 in the package) |
| Target reset | PC8 |
| LED | PC9 (bonded to PA8 in the package), lit when low |
| Bootloader key | IAP key (S1), PC7 |
| Target power switches | PA5 (3V3), PB12 (5V), held low from power-up, that is on |

In the QFN28 package PA9 is bonded to PA13, and on the board PB13 is wired to PA14, so the target's SWD lines also reach the chip's own debug pins. The application turns SWJ off at start, PA13 and PA14 stay inputs and PA9 and PB13 drive the target; while the application runs a WCH-Link cannot reach the chip, and updates go through DFU. The board's ModeS key (S2) is wired to the crystal output PD1; pressing it stops the crystal and drops USB.

The LED is lit while USB is connected to a computer, blinks with DAP traffic and is off without a connection; it blinks while the bootloader is in DFU mode. The chip has 32 KB of RAM: 2 DAP packets and a 2048-byte sampling buffer.

## linkw

WCH-LinkW-R0-1v1: CH32V208GBU6, 32 MHz crystal, full-speed USB, the chip's own 2.4 GHz radio, product name `XR-DAP-V208`. The application runs at the chip's rated 144 MHz.

| Use | Location |
|---|---|
| SWCLK | JP1 pin 2, through 100 Ω to PA5 |
| SWDIO | JP1 pin 4, through 100 Ω to PA11 |
| Target reset | JP1 pin 9, PC8 |
| GND | JP1 pin 6 |
| Power output | JP1 pin 8 3V3, pin 10 5V, switched by PA0 and PA1, held low from power-up |
| Bootloader key, pairing key | ModeS, PA4 |
| Blue and green LED | PC9, PC7, lit when low |
| BOOT key | The chip's BOOT0; held at power-up, it enters the chip's USB download mode |

The SWD lines of JP1 share their nets with the chip's debug pins PA13 and PA14. The application turns SWJ off at start, and PA5 and PA11 drive the target; while the application runs a WCH-Link cannot reach the chip.

The blue LED behaves like the `v305` LED. The green LED is lit while a debug session runs over the radio and blinks fast while pairing. The chip has no high-speed USB PHY; the DAP interface uses the two one-way endpoints EP1 OUT and EP2 IN, with 1024-byte packets as well. The firmware is linked for 32 KB of RAM: 2 DAP packets and a 2048-byte sampling buffer.

The radio driver is `boards/linkw/v208_radio.hpp`. Packets on air use the BLE packet format, with the pair's link address as access address, and the hardware does whitening and CRC. The high rate (default) is the 2M PHY, up to 251 bytes per packet, a 1024-byte message in at most 5 packets; the low rate is the 1M PHY, up to 127 bytes per packet, a message in at most 9 packets. The channels are the BLE ones, 2402–2480 MHz in 2 MHz steps.

## SWD clock

SWD is generated by GPIO in software. A requested clock at or above the speed of the undelayed path uses that path; any other request gets the delayed step with the nearest period, within half a step of the request. The steps are calibrated in CPU cycles, with the constants in each board's `board.hpp` (`kSwdStepX10`, `kSwdInterceptX10`, `kSwdFastX10`).
